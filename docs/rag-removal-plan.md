# 平台 RAG 功能移除执行方案

日期：2026-10-20
状态：代码与配置移除已实施，已完成本地自动化和浏览器验收。实际部署未执行；详细结果见第 9 节。

## 1. 目标与范围

移除 AIPI Platform 自身用于补充源码证据的向量检索链路，减少运行依赖、额外 GitHub 请求和向量化开销，保留项目分析与报告生成能力。

移除链路：

```text
额外读取 Python 源码 → AST 分块 → Ollama Embedding
→ Qdrant 索引 → 按维度语义检索 → 补充报告证据
```

保留链路：

```text
GitHub 仓库信息、README、目录树、配置与文档
→ 关键源码读取与结构解析
→ 直接证据采集、去重与持久化
→ 报告综合 → 页面、Markdown、JSON
```

必须保留：

- 识别被分析项目中的 RAG、向量库、Embedding、检索流程等技术能力。
- RAG 分析维度、相关源码识别规则和模块深挖入口。
- 普通证据采集、源码路径和行号、证据存储与报告引用。
- 跨次分析记忆、历史报告、运行记录和检查点。
- 已实施的报告重设计，包括九章正文、来源附录及历史格式兼容。
- GitHub 文件读取、源码结构提取和报告使用的大模型服务。

禁止以全局删除 `rag`、`qdrant`、`embedding` 关键词的方式实施：这些词也用于识别目标仓库的技术栈。

## 2. 移除前实现与影响评估

以下结论来自当前代码检查，未进行本次性能或报告质量对比实验。

| 当前实现 | 移除影响 |
| --- | --- |
| `RAG_ENABLED` 默认关闭，页面可按次开启 | 原本关闭时，核心证据来源基本保持一致 |
| 索引器仅处理 `.py` 文件，默认最多 80 个文件 | 主要损失是额外 Python 文件的语义证据覆盖 |
| 证据技能先合并检索证据，再合并直接分析证据 | 删除检索分支后继续执行直接证据采集 |
| 报告综合最多接收 12 条通用证据，每条截取 200 字符 | 保留该通用限制；它不是 RAG 专属配置 |
| 工厂始终注册检索工具并创建客户端 | 必须同时移除构造与导入，单关开关不能消除依赖 |
| 历史记忆使用独立的持久化仓库 | 移除向量库不要求删除历史记忆 |
| Docker 应用声明依赖 Qdrant | 删除服务时同步更新 `depends_on` |

预期可以减少开启 RAG 时的索引与检索开销，并简化部署。不能承诺报告质量自动提高；大型 Python 仓库中未被直接采样的实现细节可能更容易遗漏。

## 4. 接口与历史数据兼容策略

采用“一次完成运行链路移除，保留短期接口兼容”的方式。

### 请求

暂时保留 `enable_rag: bool | None` 字段，标记为已弃用，说明功能已移除、该参数不再生效。服务端不再读取它来创建运行配置。

这样旧页面或调用方携带 `enable_rag=true` 时仍可提交任务，但不会触发检索。新页面不再发送该字段。后续独立的接口清理版本再删除兼容字段。

### 响应

暂时保留已弃用的 `rag_enabled` 字段，统一返回 `false`，语义为当前服务不执行 RAG。不要从历史检查点恢复旧值作为当前能力状态。下一次接口清理与请求字段一起移除。

### 已有数据

- 不删除数据库中的历史证据、报告、任务或检查点。
- 旧检查点里的 `rag_enabled` 可作为无效附加字段保留；新执行路径不读取它。
- 历史检索证据仍是带路径和内容的既有记录，不依赖实时向量检索才能展示。
- 历史报告保留生成时的正文和结论，不批量重写。
- 现有检查未发现需要删除的专属业务表；实施时核对模型和迁移后确认，无需仅为清理 JSON 键新增迁移。
- 部署切换前让正在运行的分析完成，或按现有任务机制结束后重新提交，避免同一次分析混用两版执行链路。

## 7. 风险与回退

| 风险 | 处理方式 |
| --- | --- |
| 大型 Python 项目证据覆盖减少 | 明确披露读取范围；后续单独改进入口定位和关键文件采样 |
| 误删分析目标项目的 RAG 能力 | 保留维度、源码识别、深挖及其测试；按调用链删除组件 |
| 旧客户端仍传开关参数 | 使用第 4 节的弃用兼容字段 |
| 删除依赖后存在残留导入 | 在不安装已删除依赖的环境执行导入和核心流程检查 |
| 历史数据被误清理 | 不做数据库清空、检查点重写和向量卷删除 |
| 共享 Ollama 被其他项目使用 | 仅取消本项目依赖，不操作宿主机安装与模型 |

回退以恢复本次移除涉及的代码、依赖与部署配置为单位，保护其他工作中的修改，不使用整体重置覆盖工作区。保留的 Qdrant 数据卷可供恢复使用；必要时由恢复后的索引器重新构建索引。
